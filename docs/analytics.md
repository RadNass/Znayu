# Znayu — личная статистика сайта (v0.9)

**Статус:** код страницы и сбор событий подготовлены, но общие данные появятся **только после установки SQL в Supabase**. GitHub Pages сам не может хранить общую статистику всех посетителей.

## Один раз подключить базу

1. Войди в Znayu через Google или email **под своим взрослым аккаунтом**. Именно он будет видеть закрытую статистику.
2. Открой [SQL Editor твоего проекта znayu-production](https://supabase.com/dashboard/project/hanyhyujcitwjlispwlq/sql/new).
3. Открой файл [supabase/analytics_setup.sql](../supabase/analytics_setup.sql), скопируй его целиком в SQL Editor.
4. **Перед запуском** найди строку `lower('YOUR_LOGIN_EMAIL')` и замени `YOUR_LOGIN_EMAIL` на адрес, с которым ты уже входил в Znayu. Это адрес для назначения администратора; не отправляй его в открытый репозиторий.
5. Нажми **Run**. После успешного выполнения перезагрузи Znayu и войди в аккаунт снова.
6. Открой [закрытую статистику Znayu](https://radnass.github.io/Znayu/#analytics). В боковом меню появится раздел **«Статистика сайта»**.

Если SQL ещё не запущен или email в последней строке не совпал с аккаунтом, появится пояснение вместо вымышленных чисел. Если уже запускал SQL с шаблонным email, исправь его и повторно запусти: скрипт рассчитан на повторное исполнение.

## Что показывает

- Онлайн — приблизительное число взрослых согласившихся браузеров, которые отправили сигнал за **последние 150 секунд**.
- Сейчас учатся — онлайн-вкладки в уроках, диагностике и испытании.
- Посещения и уникальные посетители — открытия приложения после согласия на статистику; один браузер с постоянным случайным идентификатором считается одним посетителем.
- Авторизованные за выбранный период — количество **разных аккаунтов** среди учтённых посещений и событий.
- Входы — отдельные зарегистрированные события логина (включая некоторые OAuth-возвраты; не все повторные восстановления сессии считаются новыми входами).
- Всего аккаунтов и новые регистрации — подсчитываются **в базе Supabase Auth**, а не браузерной телеметрией.
- Начало и завершение диагностики, уроков и испытаний.
- График посещений за **сегодня, 7 дней или 30 дней**; часы/даты считаются по Алматы.
- Отчёт обновляется **каждые 20 секунд**, heartbeat клиента отправляется **раз в 60 секунд** при открытой видимой вкладке.

**Цифры до момента включения учёта восстановить нельзя.** Первый день может быть неполным. Режим школьника не отправляет события. Взрослый пользователь может запретить сбор событий. Поэтому это не полный счётчик всех реальных людей, а добровольная продуктовая аналитика.

## Конфиденциальность и защита

- По умолчанию телеметрия отключена: взрослый выбирает «Разрешить» или «Не разрешать».
- При согласии браузер сохраняет случайный UUID; при отказе удаляет его. Сохраняются только типы действий, время и UUID сессии/браузера, а для взрослых с аккаунтом — UUID авторизации.
- **Ответы на задания, ФИО, IP в таблицу, email, тексты ИИ-чата и прогресс школьников не отправляются.** Псевдонимизированные идентификаторы могут всё равно считаться персональными данными: перед публичным запуском проверь политику конфиденциальности и юридические основания обработки по законодательству Казахстана.
- Ни один пользователь не может читать сырые события через API таблицы. Публичным клиентам доступна **только INSERT** с RLS; итоговые суммы выдаёт ограниченная функция PostgreSQL с явной проверкой зарегистрированного администратора. Проверка не основывается на скрытии ссылки или JS-пароле.
- В коде **нет и не должно быть** `service_role`, `sb_secret_` и другого приватного ключа.
- Публичный доступ на запись может подвергаться накрутке. Для коммерческого масштабирования рекомендованы серверный приём с лимитами, мониторинг базы и расписание удаления старых записей.
- Автоматического удаления сырых записей **пока нет**. Добавь в Supabase Cron ежедневную очистку старше 90 дней (пример SQL в конце скрипта), установи срок хранения и отрази его в политике.

## Диагностика проблем

- **Нет кнопки «Статистика сайта»**: не авторизован администратор, SQL не запущен или страница ещё не обновлена. Открой адрес `#analytics` напрямую для объяснения.
- **Статистика пуста:** SQL установлен только что, аудитория не дала согласия либо все пользователи в школьном режиме.
- **Нет онлайн:** вкладки неактивны, согласие отклонено или прошло более 150 секунд с последнего сигнала.
- **Ошибка доступа:** проверь адрес в последней строке `analytics_setup.sql` и то, что используешь именно этот аккаунт Znayu.
- **Ошибка «function not found»:** весь SQL не выполнен либо выполнен в другой проект Supabase.

Не публикуй эту панель для обычных пользователей: она предназначена только для администратора.
